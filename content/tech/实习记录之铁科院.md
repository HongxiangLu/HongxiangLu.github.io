## 26-09-17

### 数据范围

本次工作以原始文件《桥梁工程验收标准条款统计7.3.xlsx》为基础，将分散在多个工作表中的桥梁工程验收条款整理为一张结构统一、无合并单元格、便于筛选和后续导入的数据表，并在后续对话中逐步调整字段、样式和工程分类信息。

处理范围为原工作簿中从「4 明挖基础」到「19 沉降变形观测」的全部14个工作表。将其内容合并到单一工作表中，保留原工作表顺序及各工作表内部的数据行顺序，同时去除各工作表顶部跨列合并的说明性标题，包括工程名称、汇总数量等文字，不将这些标题作为数据记录。

最终形成2,535条数据记录，不含字段表头行和原表末尾没有实际数据的空白行。

### 字段映射与隐藏数据处理

对于「施工质量验收标准」以外的字段，按原表表头进行对应映射，避免因各工作表列位置不同而发生数据错位，主要涉及：分部工程、分项工程、检验项目类型、规范条款、指标、是否可量化指标、取值范围／参数取值范围。

例如，部分工作表中的「指标」「是否可量化指标」排列顺序不同，汇总时按名称对应到统一字段；将原表中的「取值范围」统一命名为「参数取值范围」，原单元格内容按对应关系保留。

经核对，原表存在用户在常规视图中看不到的隐藏列，包括部分：序号、分项工程序号、关键指标／关键量化指标、关键指标权重、分级阈值、级数、分值等级、无表头但有数据的辅助列等。最终按各工作表实际隐藏状态排除这些列。部分工作表的第四个验收细目子列也处于隐藏状态，按上述口径未纳入。

但是，原表中的隐藏数据行仍保留。「18 涵洞」第211—224行共14行处于隐藏状态，仍纳入汇总数据。

### 合并单元格拆分与工程名称补全

新表中未保留任何合并单元格，确保每条记录以普通单元格形式保存。拆分合并单元格没有增加数据行，只改变原有行中相关字段的表达方式。

1. 对于原表「分部工程」列的合并单元格，将原合并区域中的名称填入该区域对应的每一条记录。

2. 对于原表「分项工程」列的合并单元格，同样将原合并区域内容填入拆分后的各行。

3. 除「19 沉降变形观测」外，如果完成合并区域补全后，「分项工程」仍为空，则在同一工作表内向上寻找最近的非空「分项工程」值，并填入当前行。「19 沉降变形观测」不执行这一普通空白向上补全规则，其「分项工程」空白按原表保留。

4. 「分部工程」没有额外应用普通空白向上补全规则，仅按原合并区域展开填值。

### 施工质量验收标准的层级拆分和空白补全规则

将原表「施工质量验收标准」下的子列，按从左到右的顺序映射为一级、二级、三级、四级验收细目。不足四级时，其余列保留为空，或按后续明确的补全规则处理。上述映射以排除隐藏列后的有效子列为准。

对于「施工质量验收标准」中的合并单元格，取消合并，只在其最左侧对应的细目列保留原内容，不将同一内容横向复制到其他细目列。

「5 承台」「7 墩台」两个工作表的「施工质量验收标准」表头范围内，最后一个子列实际存放规范条款或相应原始内容，因此将其映射到新表的「规范条款」列，其前面的子列按顺序映射到验收细目字段。映射时保留原始内容，未根据字段名称另行改写单元格中的数值、允许偏差或文本。

验收细目的空白补全限定在同一原工作表内部进行，不跨工作表继承，具体规则如下：

1. 对于某行中的一个非空验收细目，只有当其左侧所有验收细目列均为空时，才对左侧各列执行补全。分别在每一个待补列中向上寻找最近的非空值，并填入当前行对应列。

2. 如果该非空细目左侧已经存在任意一个非空细目，则不对左侧其他空白列继续补齐。例如，一级、二级均为空而三级非空时，分别补齐一级、二级；一级非空、二级为空而三级非空时，不补二级。

3. 如果某行的有效验收细目子列全部为空，则继承上一行完成前述规则处理后的验收细目内容。继承的是整理后的上一行结果，而不是未经补全的原始值。

4. 上述规则仅用于验收细目，未扩展到其他字段。

### 字段补充和删改

首次汇总时，在新表最左侧增加「单位工程」列，每条记录填入其来源工作表的完整名称，例如「4 明挖基础」「5 承台」「13 拱桥」「19 沉降变形观测」等。该字段保留原工作表编号和名称，用于识别记录所属的工程类别及来源。

后续又在其最左侧新增「单项工程」列，全部2,535条数据均填入「桥梁工程」，原有各列整体右移，其他字段、数据和样式保持不变。

在汇总表形成后，先后删除「序号」「编号」两列，未删除任何数据行，删除后最初整理得到的汇总表保留12个字段。

### 2,529项与2,535行的数量差异分析

原始文件「4 明挖基础」顶部说明文字标注共涉及2,529项评价条款，其中主控项目1,195项、一般项目1,334项、可量化1,923项、目前不可量化606项。该说明为固定文字，并非根据明细自动计算的公式。

逐表核对后，14个工作表共有2,535条纳入记录，每条汇总记录均可对应到原表数据行，没有因拆分合并单元格或补齐层级信息而新增行。针对与原表标注相差的6行，进行了以下核对：

1. 按「是否可量化指标」统计，“是”有1,923行、“否”有519行、空白有93行。其中“是”的数量与标题一致，“否”与空白合计612行，比标题中的606多6行。但不能据此认定空白都属于不可量化，也不能确定哪6行应删除。

2. 按原合并单元格的含义展开「检验项目类型」进行计数，得到主控项目1,200行、一般项目1,331行，以及4行未正常填写项目类型的说明性记录，与标题标注不一致。该展开仅用于统计分析，未借此修改汇总表中原先保留的「检验项目类型」值。

3. 「13 拱桥」第45、46、131、132行涉及“按[A]第7.2节墩身标准执行”“根据不同结构类型按[A]标准相关规定进行验收”等说明性内容，未正常填写主控／一般项目类型。即使排除这4行，仍为2,531行，不能完全解释与2,529的差额，因此未删除这些记录。

4. 「18 涵洞」第211—224行共14个隐藏行已纳入。若排除这些行，总数为2,521，也不是2,529，因此隐藏行不能直接解释这6行差异。

目前能够确认的是，原表标题中的汇总数字与当前明细不一致。可能原因包括标题沿用较早版本、明细修改后未同步更新统计，或原统计采用了未说明的条款计数口径。仅凭当前文件不能确定具体原因，因此保留全部2,535条来源记录，没有为了匹配标题数量而人为删行。

## 26-09-18

### Excel 输入与图谱结构

制定以下规则用于将整理后的 Excel 验收数据导入 Neo4j，形成具有工程层级、施工质量验收标准细目层级及具体指标记录的知识图谱，用于后续按工程和细目查询、展示验收内容，并为问答及 RAG 检索提供结构化数据基础。

脚本尽量保持单文件、逻辑直接，仅保留避免错误导入所必需的检查，不额外引入复杂校验体系、测试文件或数据治理功能。尽量使用一个 Python 脚本完成 Excel 读取、记录编号生成与回写、Neo4j 约束处理及图谱导入。

#### 1. 数据文件业务列

| 类别 | 列名 |
|---|---|
| 工程层级 | 单项工程 |
| 工程层级 | 单位工程 |
| 工程层级 | 分部工程 |
| 工程层级 | 分项工程 |
| 细目层级 | 施工质量验收标准一级细目 |
| 细目层级 | 施工质量验收标准二级细目 |
| 细目层级 | 施工质量验收标准三级细目 |
| 细目层级 | 施工质量验收标准四级细目 |
| 指标名称 | 指标 |
| 指标属性 | 检验项目类型 |
| 指标属性 | 规范条款 |
| 指标属性 | 是否可量化指标 |
| 指标属性 | 参数取值范围 |

另设技术列：`记录编号`，可以在首次运行时由脚本新增。其余必需业务列缺失时，应明确报错。

#### 2. 图谱整体结构

采用以下六种节点标签：`单项工程`、`单位工程`、`分部工程`、`分项工程`、`施工质量验收标准细目`、`指标`。其中「施工质量验收标准细目」可以分为四个层级，但不要求补齐所有层级。

#### 3. 节点属性

`单项工程`、`单位工程`、`分部工程`和`分项工程`节点仅保存：`id`、`name`。

一级至四级细目统一使用`施工质量验收标准细目`标签，仅保存：`id`、`name`、`层级`。「层级」表示原表中的细目列级别，不表示到根节点的实际边数。例如，一级细目直接连接三级细目时，三级节点仍保存`层级=3`，不能改为2。

#### 4. 空层和占位内容的处理

整理后的表格按行读取，不再使用全表`ffill()`，也不从上一行自动继承。每行明确填写的内容就是该记录的输入。

空工程层：空工程层跳过，不创建空名称工程节点。分项工程为空时，由分部工程直接连接该行首个有效细目。

空细目层：空细目单元格不建立节点，中间细目为空时，上一个有效层直接连接后一个有效层，不调整后续细目的原始层级值。例如：一级细目有值 → 二级细目为空 → 三级细目有值，导入为：一级细目 → 三级细目 → 指标。

占位字符串：`/`、`否`等非空字符串按普通内容处理。细目为`/`时，建立`name="/"`的细目节点。只有实际为空的细目才跳过。

#### 5. 关系类型与指标挂载

关系类型：仅使用`包含`和`包含指标`两种关系。`包含`用于工程层级之间、工程与细目之间、细目与细目之间；`包含指标`用于当前行最后一个有效层级节点与指标节点之间。

挂载位置：每条指标记录只挂到当前行最后一个有效层级节点。有细目时，挂到最深的有效细目；没有细目时，挂到最后一个有效工程节点。不把同一指标重复连接到全部祖先节点，指标的上级工程和细目通过关系路径查询。

下级结构：同一个细目节点可以通过`包含`连接下级细目，同时通过`包含指标`连接直接指标，以容纳在不同层级结束的记录。例如，一条记录只填写到细目A，指标X直接挂在A下；另一条记录填写到A下的细目B，指标Y挂在B下。不应为了统一深度而人为补充子项。

### 节点身份与指标记录

#### 1. 节点名称与唯一身份

`name`用于展示，不作为节点唯一身份，不对上述业务标签的`name`设置唯一约束。同名指标可以有多个节点，不同父路径下的同名工程或细目也可以有多个节点。创建节点、更新节点和建立关系均按`id`定位。

| 节点 | 身份依据 |
|---|---|
| 单项工程 | 标签＋名称，父节点为空 |
| 单位工程 | 标签＋父节点ID＋名称 |
| 分部工程 | 标签＋父节点ID＋名称 |
| 分项工程 | 标签＋父节点ID＋名称 |
| 细目 | 标签＋父节点ID＋原始细目层级＋名称 |

当前脚本使用上述信息生成确定性的 UUID5。同一父路径下，相同层级、相同名称的节点可以复用；不同父路径下的同名节点不合并；同一父节点下，不同来源层级的同名细目不合并。不单纯使用名称执行全库合并。层级ID与指标ID的区别如下：

层级ID：工程和细目ID依赖路径，修改上级名称、增加顶层或调整路径，可能改变下级层级节点ID。

指标ID：来自 Excel 记录编号，不依赖名称、范围或路径。指标移动到新路径时，继续使用原记录编号。

#### 2. 指标记录粒度

每条有效 Excel 记录对应一个独立指标节点，不按指标名称去重，不因工程路径、细目路径和指标名称相同而合并记录，也不因取值范围不同而覆盖前一条记录。同一记录编号重复出现在多行时，应报错，避免相互覆盖。

`指标`节点表示带有具体工程上下文、细目和验收属性的一条记录，不是全库共享、只表示「温度」「强度」等抽象概念的指标词条。

复合指标整体作为一个指标节点的名称保存。例如，「屈服强度、抗拉强度、伸长率、冷弯性能」作为完整名称导入。不按逗号、顿号或分号自动拆成多个指标节点，因为参数范围不一定能与拆分后的内容一一对应。

#### 3. 指标固定属性

| 属性 | 来源 |
|---|---|
| `id` | Excel「记录编号」 |
| `name` | Excel「指标」 |
| `检验项目类型` | 同名列 |
| `规范条款` | 同名列 |
| `是否可量化指标` | 同名列 |
| `参数取值范围` | 同名列 |

「记录编号」映射为`id`，不重复增加同值的「记录编号」属性。

指标为空时，保存`name=""`，使用空字符串，不使用一个空格，也不用细目名称或完整路径替代。空名称节点仍然存在，并通过独立ID区分。

「检验项目类型」「规范条款」「是否可量化指标」「参数取值范围」为空时，均保存为空字符串`""`，确保属性键仍然存在。不使用`null`，因为在 Neo4j 中将属性设置为`null`会移除该属性。

#### 4. 文本格式处理

空单元格转换为空字符串，非空值按文本形式导入，当前脚本统一使用字符串。去除首尾无意义空白，将 Windows 换行统一为`\n`，保留内部换行。

`/`保留为`"/"`，`否`保留为`"否"`。不把空的「是否可量化指标」解释为“否”，不额外派生`可量化=true/false`。「规范条款」列中的数值、偏差或其他非条款文本也保存在原属性中。

数学符号、百分号、千分号、单位、条件语句及上下偏差按原文保留。不擅自修正原文中的名称差异，工程名称中的编号前缀按原文保留。

#### 5. 记录编号生成与回写

在原 Excel 表格中新增`记录编号`列，编号写入对应记录所在行。

已有非空编号继续使用；编号为空时生成新编号，当前实现格式为`ZB-`加 UUID4 十六进制字符串。编号以固定文本值保存，不使用基于行号的公式，也不将 Excel 行号作为长期记录身份。

记录排序、插入或移动时，编号应随整条记录移动。修改已有记录内容时保留编号，复制记录作为新记录时须分配新编号，不能每次导入都重新编号。

先读取并检查所有记录，发现重复编号或缺少必需顶层内容时，不开始数据库导入。新编号成功保存到 Excel 后，才进行数据库写入。Excel 保存失败时，停止处理，不继续清空或导入数据库。没有新增编号和表头时，不必再次保存 Excel。
